# Научная новизна проекта

## 1. Формулировка научной новизны

Разработан и программно реализован метод **интеллектуального анализа нарушений в SRM‑системах** для сервисного центра ремонта техники на основе:

1) **динамической интерпретации онтологии нормативных правил** (правила загружаются из JSON во время выполнения и применяются без изменения кода);  
2) **мультиагентной модели анализа** (каждый агент применяет только свой класс правил и формирует унифицированные результаты);  
3) **агрегированной математической модели риска поставщика** (risk score 0–100 с весами из онтологии);  
4) **объяснимого вывода** (сохранение: какое правило сработало, какие значения сравнивались, почему это нарушение);  
5) **рекомендаций по управленческим действиям** (rule‑based, без внешних сервисов).

Метод ориентирован на локальный запуск (offline‑first) и воспроизводимость результатов.

## 2. Что реализовано в программном продукте

### 2.1 Онтологическая модель правил (динамический слой)

- Правила описываются формализованной структурой:
  - `rule_code`, `rule_name`, `rule_type`, `target_entity`
  - `condition`, `threshold`, `weight`, `risk_impact`
  - `explanation_template`, `recommendation_template`, `is_active`
- Правила загружаются из JSON и интерпретируются в рантайме.
- Пример файла: `examples/repair_rules_ontology.json` (раздел `rules`).

### 2.2 Мультиагентная архитектура

Реализованы специализированные агенты, каждый применяет только свой класс правил:

- `BudgetAgent` — бюджетные правила
- `SupplierStatusAgent` — статус поставщика (whitelist/blacklist и др.)
- `DeliveryAgent` — сроки поставки
- `WarrantyAgent` — гарантия
- `PriceOutlierAgent` — ценовые аномалии
- `SupplierRiskAgent` — риск‑правила (например, низкий рейтинг)
- `RepeatViolationAgent` — агрегированное правило повторяемости (post‑analysis)
- `CompositeAgent` — оркестрация, дедупликация

### 2.3 Математическая модель риска поставщика (0–100)

Risk score рассчитывается как взвешенная сумма компонент (веса извлекаются из онтологии правил):

```
risk_score = min(100,
    Wb * budget_score +
    Wd * delivery_score +
    Ws * supplier_status_score +
    Ww * warranty_score +
    Wr * repeat_violation_score +
    Wp * price_outlier_score
)
```

Уровни риска:
- 0–24: `low`
- 25–49: `medium`
- 50–74: `high`
- 75–100: `critical`

Система сохраняет историю риска поставщика (`supplier_risk_history`) и может строить динамику.

### 2.4 Explainability (объяснимость)

Для каждого нарушения сохраняется:
- `rule_code`, `rule_name`, `rule_type`, `risk_impact`, `weight`
- `compared` — значения, участвовавшие в условии
- `cause` — почему это нарушение
- `recommendation` — управленческое действие

В web‑интерфейсе есть карточка нарушения с расшифровкой.

### 2.5 Рекомендации

Рекомендации формируются автоматически на основе:
- шаблонов правил (`recommendation_template`),
- типа нарушения и уровня риска (rule‑based логика, без LLM).

## 3. Экспериментальное сравнение с базовым подходом

Добавлен модуль сравнения методов:
- `baseline` — статические проверки (упрощённая логика)
- `proposed` — онтология + мультиагенты + explainability

Метрики:
- `precision`, `recall`, `f1-score`
- количество нарушений
- количество объяснённых нарушений
- количество сформированных рекомендаций
- время анализа

Запуск:
```
python -m srm.cli experiment-risk
```

Артефакты:
- `outputs/experiments/risk_comparison.json`
- `outputs/experiments/risk_comparison.csv`
- `outputs/experiments/plots/*.png`

## 4. Положения, выносимые на защиту

1) Метод динамической интерпретации правил из онтологии в SRM‑анализе.  
2) Мультиагентная архитектура как способ масштабировать набор проверок и повышать расширяемость.  
3) Модель агрегированной оценки риска поставщика (0–100) с весами из онтологии.  
4) Explainability‑механизм: сохранение причин, сравниваемых значений и рекомендаций.  
5) Экспериментальная верификация и сравнение с базовым подходом.

## 5. Отличие от Excel

- Excel фиксирует формулы вручную; система **интерпретирует правила из онтологии** в рантайме.
- Excel не поддерживает мультиагентный анализ; система запускает независимых агентов и объединяет результаты.
- Excel не ведёт историю риска поставщика и не формирует управленческие рекомендации автоматически.
- Excel не предоставляет единый explainability‑слой (“почему это нарушение и что делать”).
